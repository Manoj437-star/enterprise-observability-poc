# Observability Troubleshooting Runbook & SOPs

This runbook provides actionable procedures for Site Reliability Engineers (SREs) responding to alerts generated by this platform.

---

## 1. Alert: `KubernetesPodCrashLooping`
- **Severity:** Warning
- **Threshold:** `increase(kube_pod_container_status_restarts_total[5m]) > 0`
- **Triage Steps:**
  1. Identify crashing pod:
     ```powershell
     kubectl get pods -A | Select-String "CrashLoop|Error"
     ```
  2. Inspect previous container crash logs:
     ```powershell
     kubectl logs -n <namespace> <pod-name> --previous --tail=50
     ```
  3. Query Log Analytics for exit code:
     Run `kql/3-application-failures.kql` to check for exit code 137 (OOMKilled) or 1 (Application Exception).
  4. Remediate:
     - If OOMKilled: Increase container `resources.limits.memory`.
     - If application bug: Roll back deployment to previous stable revision:
       ```powershell
       kubectl rollout undo deployment/<name> -n <namespace>
       ```

---

## 2. Alert: `HostHighCpuLoad`
- **Severity:** Warning
- **Threshold:** Node CPU utilization > 80% for 3 minutes
- **Triage Steps:**
  1. Identify top resource consumers:
     ```powershell
     kubectl top pods -A --sort-by=cpu
     ```
  2. Check if a single container is rogue or if aggregate node capacity is exhausted:
     Open Grafana Dashboard `2. Kubernetes Node Monitoring`.
  3. Remediate:
     - Apply Horizontal Pod Autoscaler (HPA) or decrease replica count of non-critical workloads.
     - If persistent, increase node pool capacity in `terraform/aks.tf`.

---

## 3. Alert: `SampleAppHighErrorRate`
- **Severity:** Critical
- **Threshold:** HTTP 5xx error rate > 5% for 2 minutes
- **Triage Steps:**
  1. Open Grafana Dashboard `4. Application Performance Monitoring (APM)` to isolate error status codes.
  2. Open Jaeger UI (`http://localhost:16686`) and search for traces where `http.status_code >= 500`.
  3. Inspect trace waterfall to find failing downstream dependency or database timeout.
  4. Query Log Analytics using `kql/1-container-errors.kql` to view exact error stack traces.

---

## 4. Alert: `SLOAvailabilityBurnRateCritical`
- **Severity:** Critical
- **Threshold:** 1-hour burn rate > 14.4x (rapidly consuming 30-day error budget)
- **Triage Steps:**
  1. Open Grafana Dashboard `6. SLO & SLA Management`.
  2. Review Error Budget Remaining gauge.
  3. Check recent deployments or configuration changes applied to the cluster.
  4. Initiate incident response bridge and halt production deployments if error budget is depleted (<0%).
